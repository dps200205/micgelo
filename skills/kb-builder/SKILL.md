# 知识库生成

把美术资料转成评审工具可以直接使用的**知识块草稿**。产物由人审核后才生效。

## 必读资料

开始前读取：
- `references/知识库编写规范.md`：目录、卡片、评审标准、问题库、图片的格式要求。
- `references/编译规则.md`：评审标准 → `questions.yaml` 的规则。
- `references/样板_点线面/`：优秀样板。新知识块的详细程度和写法以它为准。
- 目标知识库已有的 `questions.yaml`：有同义问题时原样复用。

## 工作流程

### 1. 摄入资料
- **视频**：转写语音，保留时间码；需要案例图时运行 `scripts/extract_frames.py` 抽关键帧。没有转写能力时，请用户提供文字稿。
- **文档**：提取正文，去掉口语化重复内容。
- **图片**：判断用途。项目规定的标准样式 → 参考图 `reference`；合格或不合格示范 → 案例图 `example`。无法判断时询问用户。

### 2. 抽取知识点
整理出定义、候选条目、例外情况、修改方法。每一项记录**出处**（时间码、页码或文件名）。

- 只抽取资料中有依据的内容。资料未提及的判断标准不要补写；确实必要时标为“【待确认】”。
- 讲师的经验提示（如“约占一半画幅”）不能写成硬性阈值。

### 3. 确定位置
- 根据目标知识库的目录决定放在哪个文件夹。美术原理放美术基础知识库；项目规范放项目知识库对应的图类型节点下。
- 判断内容是否和已有知识块重叠。重叠时优先扩充原知识块，并在卡片“与其他知识块的关系”中写明边界。
- 知识块的粒度：一组可以一起评的条目，通常 5–20 条。过多就拆分。

### 4. 编写文件
按模板（`templates/`）生成：
1. **知识块卡片**：“什么时候不评”要写具体反例，不能写“特殊情况除外”。“条目索引”每条一行。
2. **评审标准**：每条必须有适用条件、判断说明、观察要点、合格表现、不合格表现、不合格时。推荐写易混淆。
   - 观察要点写图上能直接看到的现象，每条只说一件事，通常 1–3 条。
   - 不合格时写清对象、动作、期望效果。
   - 术语对照表要给出抽象术语对应的英文观察描述。
3. **`cases.yaml`**：登记图片。没有图片就写 `images: []`。

### 5. 编译问题库
按 `references/编译规则.md` 生成 `questions.yaml`：
- 一条观察要点对应一个检查，写 `point` 序号。
- 问题和 criteria 只用英文；图中元素用 `{subject}`、`{item}` 槽位；比对参考图用 `{ref:名称}`。
- 不问决策（如 “Is this good?”），决策由判定规则决定。
- 槽位优先用内置的 `subject`、`repeated_groups`、`guiding_lines`、`large_areas`、`dense_regions`、`point_groups`。只有确实需要新元素类型（如包点）时才声明新槽位。
- 条件和判定只能使用规范中列出的 `brief` 字段，不要自创字段。

### 6. 自检
运行 `python scripts/lint/lint_kb.py --kb <知识库路径>`，修改到错误清零；警告逐条判断。无法运行脚本时，逐项对照规范自查，并在交付时说明未运行检查。

### 7. 交付审核
- 卡片状态写 `草稿`。**不要自行改为“可用”**，由人审核后修改。
- 向用户列出：每条条目的出处；编译出的问题及中文含义；所有推断和【待确认】内容；资料之间矛盾的地方。

## 质量底线

- 宁可少写条目，也不要编造标准。
- 一条条目只判一件事；“A 或 B”是两个判断时要拆开。
- 条目要有区分力：能举出一张合格的图和一张不合格的图。举不出来的条目不要写。
- 问题不能包含某一张图的具体内容。

## 替换说明

这个 skill 可以整体替换。评审工具读取 `SKILL.md` 和 `references/` 下的全部文本作为生成上下文，输出格式由工具另行指定。替换时保持 `SKILL.md` 在压缩包根目录或唯一子目录下即可。
