# 知识库编写规范 v2.0

本规范规定 CFM 场景概念设计知识库的目录结构、文件格式与写法。人工编写、AI 生成（知识库生成 skill）都必须遵守。评审工具依赖这些格式完成检索与出题，格式不对时工具会报错。

样板：`场景美术基础知识库/平面构成/场景概念设计中的点线面/`，新建知识块时以它为准。
模板：`_规范/模板/`。

---

## 一、三层结构

```
知识库根/
├─ ！知识库说明.md                  ← 根卡片：入口说明
├─ _规范/                           ← 以 _ 开头的文件夹不参与检索
├─ 场景美术基础知识库/  (kb: basic)
│  ├─ ！什么时候评审场景美术基础.md  ← 文件夹卡片
│  └─ 平面构成/
│     ├─ ！什么时候评审平面构成.md
│     └─ 场景概念设计中的点线面/     ← 知识块（最小评审单位）
│        ├─ ！什么时候评审点线面.md  ← 知识块卡片（检索用）
│        ├─ 01点线面的评审标准.md     ← 评审标准（人读，出题依据）
│        ├─ questions.yaml            ← 问题库（机器读，由标准编译）
│        ├─ cases.yaml                ← 图片登记表
│        └─ images/                   ← 案例图、参考图
└─ 项目知识库/  (kb: project)
   └─ 01_局内场景/01_PVP场景/01_常规爆破地图/   ← 图类型节点
      └─ 场景中的色彩使用规范/                  ← 项目知识块
```

| 层级 | 作用 | 必须有的文件 |
|---|---|---|
| 文件夹 | 分类、缩小检索范围 | 一个 `！` 开头的文件夹卡片 |
| 知识块 | 一组可以一起评的条目，例如“点线面” | 知识块卡片、评审标准、questions.yaml、cases.yaml、images/ |
| 条目 | 一条可判定的标准，例如 D04 | 写在评审标准里，编号全块唯一 |

**两个知识库：**
- **美术基础知识库**：通用的美术原理，按知识领域分类。
- **项目知识库**：项目规范，按“场景类型 → 图类型”分类。结论冲突时以项目知识库为准。

## 二、命名

- 每个文件夹里**有且只有一个** `！` 开头的卡片文件，命名为 `！什么时候评审<名称>.md`。
- 文件夹可以带序号前缀 `01_`，序号只用于排序。
- 知识块 ID 用小写英文，全库唯一，例如 `dlm`、`bomb_color`。评审工具的配置、标注和报告都通过这个 ID 引用知识块。
- 条目编号用“大写字母 + 两位数字”，例如 `D01`，在本知识块内唯一。全局引用写成 `知识块ID.条目编号`，例如 `dlm.D04`。
- 图片文件名写成 `<用途>_<条目>_<描述>.<png|jpg>`，例如 `ex_D04_焦点被高光抢走.jpg`、`ref_包点纹饰.png`。

## 三、卡片（`！` 文件）

卡片供检索时快速判断“要不要往下看”，必须写短、写具体。开头是 YAML 头信息，后面接固定的小节。

```yaml
---
level: block          # root | folder | block
kb: basic             # basic | project（子文件夹继承上级，可省略）
id: dlm               # 知识块必填
status: 可用          # 可用 | 草稿 | 待建设（只有“可用”的知识块参与评审）
version: 2.0
updated: 2026-10-28
standard: 01点线面的评审标准.md   # 知识块必填
questions: questions.yaml          # 知识块必填
---
```

| 小节 | 文件夹 | 知识块 | 写法 |
|---|---|---|---|
| `## 一句话定位` | 必填 | 必填 | 一句话说清楚检查什么 |
| `## 什么时候评` | 必填 | 必填 | 触发信号，逐条列出，写成能从用户输入或图上看出来的条件 |
| `## 什么时候不评` | 必填 | 必填 | 具体反例。不能写“特殊情况除外”这类说法，因为检索时无法据此判断 |
| `## 需要的信息` | 可选 | 必填 | 评审要用到哪些用户说明、哪些图中元素 |
| `## 与其他知识块的关系` | — | 必填 | 和哪些知识块有重叠，重叠时以谁为准 |
| `## 条目索引` | — | 必填 | 表格：条目、标题、何时适用、看什么。每条一行 |

检索分三步逐层披露：
1. 读文件夹卡片的“一句话定位、什么时候评、什么时候不评”，决定进入哪些文件夹；
2. 读知识块卡片的同样三节，决定评哪些知识块；
3. 读知识块的“条目索引”，决定评哪些条目。

正常情况下不需要读评审标准全文。

## 四、评审标准（人读，同时是出题依据）

结构固定：

1. YAML 头信息：`id`、`version`、`updated`。
2. `## 一、核心概念`：定义，以及**术语对照表**（术语 → 画面上看到的是什么 → 英文观察描述）。编译时把抽象术语转写成可观察的问题，靠的就是这张表。
3. `## 二、评审条目`：每条一个 `### 编号｜标题`，下面按顺序写以下字段：

| 字段 | 必填 | 写法 |
|---|---|---|
| `**适用条件**` | 是 | 什么图、什么目标下才评这一条；与条目索引的“何时适用”一致 |
| `**判断说明**` | 是 | 完整的判断依据，写给人看 |
| `**观察要点**` | 是 | 1–3 条**图上能直接看到的现象**，每条只写一件事。编译时一条观察要点大致对应一个问题 |
| `**合格表现**` | 是 | 合格时画面上看到的具体情形 |
| `**不合格表现**` | 是 | 不合格时画面上看到的具体情形，不能只写“不是合格表现” |
| `**易混淆**` | 推荐 | 容易误判的情况，以及区分方法 |
| `**不合格时**` | 是 | 修改方法：对象 + 动作 + 期望效果 |
| `**案例**` | 可选 | `cases.yaml` 中的图片 ID |
| `**参考图**` | 项目规则推荐 | 需要比对的标准图片，写 `ref_` 开头的图片 ID |
| `**出处**` | AI 生成时必填 | 依据来自哪里，例如“课程视频 00:42:10–00:44:30”“项目规范文档 第 3 页”，便于人工核对 |

4. `## 三、怎样给出结论`：给人工评审的说明。自动评审的阈值在评审工具的配置里，不写在这里。

**写法要求：**
- 一条只判一件事。“A 或 B”“A 且 B”是两个判断时，要拆成两条观察要点。
- 写图上看得见的现象，例如“地面黄线把视线带到走廊尽头”，不要写抽象评价，例如“引导感强”。
- 有意为之的例外，例如留白、刻意孤立、均匀纹样，写进“适用条件”或“易混淆”，避免误判为不合格。
- 计数、比例、左右比较这类工作交给工具，不要写成“左右各占 50%”这类需要模型计算的标准。

## 五、questions.yaml（机器读）

由评审标准编译生成，**不手工改措辞**。要改问题时，先改评审标准，再重新编译。

```yaml
block: dlm
source: 01点线面的评审标准.md
source_version: 2.0
slots: {}                 # 本块额外用到的场景元素槽位，如 {lists: [bombsites]}
refs: {}                  # 参考图：名称 -> {file: images/ref_xxx.png, desc: 英文描述}
observations: {...}       # 观察问题（英文）
clauses: {...}            # 条目 -> 适用条件 + 引用哪些问题 + 判定方式
```

字段说明和自动检查规则见 `review_pipeline/lint_kb.py` 与 `_规范/模板/questions模板.yaml`。要点：
- 问题用英文，一次只问一件事，`criteria` 里分别描述“是”和“否”的具体情形。
- 图中具体元素用槽位 `{subject}`、`{item}` 表示，不写某一张图里的具体内容。
- 参考图用 `{ref:名称}` 引用，工具会把对应图片随请求一起发给 Jev。
- 其他知识块里已经有同义问题时，原样复制该问题（文本完全一致），工具会自动合并成一次提问。

## 六、图片：cases.yaml 与 images/

知识块里的图片有两种用途：

| role | 用途 | 会不会发给 Jev |
|---|---|---|
| `reference` | **参考图**：项目规定的标准样式，如固定纹饰、标准标识 | 会，被问题用 `{ref:}` 引用时随请求发送 |
| `example` | **案例图**：某条目的合格或不合格示例，带说明 | 不会；条目出问题时附在大模型交接包里，供复核和给修改建议时参考 |

```yaml
images:
  - id: ref_包点纹饰
    file: images/ref_包点纹饰.png
    role: reference
    desc: 包点固定纹饰的标准样式（正面、无透视）
  - id: ex_D04_焦点被高光抢走
    file: images/ex_D04_焦点被高光抢走.jpg
    role: example
    clauses: [D04, D13]
    label: 不合格        # 合格 | 不合格
    note: 右侧机柜高光比走廊尽头更亮，第一眼落在右侧
```

图片要求：PNG 或 JPEG，短边至少 280 像素，长边超过 1568 像素时会被自动缩小。参考图要裁到只剩目标本身，背景越干净越好。

**注意区分**：用来校准准确率的“整图逐条人工标注”属于评测集，放在评审工具的 `cases/` 目录，不放在知识块里。

## 七、版本

- 改评审标准后要更新 `version`，并重新编译 `questions.yaml`，使两者的 `source_version` 一致。lint 会检查这一点。
- 卡片的 `status` 只有标为“可用”时，该知识块才会参与自动评审。
