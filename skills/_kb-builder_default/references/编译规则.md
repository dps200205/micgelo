# 编译提示词：评审标准 → questions.yaml

> 每个知识块只编译一次；评审标准改动后重新编译。完成后必须运行 `python lint_kb.py`，错误清零、警告逐条确认，再把卡片状态改为“可用”。
> 规范见 `知识库/_规范/知识库编写规范.md`；样板见点线面知识块的 `questions.yaml`。

## 输入
1. 知识块的评审标准 md。每条条目必须有：适用条件、观察要点、合格表现、不合格表现。
2. 卡片中的“需要的信息”。
3. 其他“可用”知识块的 questions.yaml，用来复用已有问题。

## 规则

**一条观察要点 → 一个检查**
- 每条观察要点编译成一个观察问题，检查上写 `point: 序号`。lint 会核对数量是否对得上。
- “合格表现”写进 `criteria.true` 或 `criteria.false` 里好的那一侧，“不合格表现”写进另一侧，都写成具体情形。
- “易混淆”用来调整措辞，排除容易混淆的情况。例如点线面 D13：“紧挨主体的高光不算竞争”，问题因此写成 “highlights far away from {subject}”。

**适用条件**
- 能由用户说明或场景元素机器判断的，写进 `applies_if`，例如 `scene.guiding_lines`、`brief.goal != uniform_pattern`。
- 不能机器判断的，留给第一步的大模型在路由时决定。
- 标准写明“可以合格”的例外，例如留白、刻意孤立、均匀纹样，用 `soft: true` 或 `applies_if` 处理。

**问题写法**（遵循 typesafe-ai skill）
- 英文；一次只问一个判断；“是”的含义要明确，不用双重否定。
- 问看得见的东西，抽象术语按评审标准的“术语对照表”转写。
- 不问决策，例如不写 “Is this good?”、“Should …”。
- 图中元素用槽位：`{subject}`，或 `over` 加 `{item}`；不写某张图的具体内容。槽位值自带冠词，模板中不写 “the {”。
- 需要比对标准图样时，在 `refs` 中登记参考图，问题里写 `{ref:名称}`。参考图要裁到只剩目标本身。
- 左右比较、计数、比例交给代码，例如用 `image: halves`。
- choice 的选项名用描述内容的 snake_case。

**复用**
- 其他知识块已有同义问题时，**原样复制**问题和 criteria，工具会把文本完全相同的问题合并为一次提问。

**元信息**
- `block` 与卡片 id 一致；`source_version` 与评审标准的 version 一致。
